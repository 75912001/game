# 解决方案 (已执行)
    1.  **攻击逻辑**:
        *   **目标选择**: 
            *   在 `Update` 中，如果当前没有攻击目标或目标已死亡/超出范围，遍历所有存活的怪物。
            *   计算角色与怪物的距离。
            *   选择距离最近且在攻击范围内的怪物作为目标。
            *   如果当前已有目标且仍在范围内，保持锁定（避免频繁切换）。
        *   **攻击触发**:
            *   当有合法目标且冷却时间结束时，触发攻击。
            *   播放攻击动画。
            *   造成伤害（扣除怪物 HP）。

    2.  **死亡特效 (马赛克崩解)**:
        *   **状态管理**: 怪物增加 `IsDying` 状态和 `DeathTimer` 计时器。
        *   **触发时机**: 当 HP <= 0 时，进入 `IsDying` 状态，初始化计时器（例如 1秒）。
        *   **渲染效果**:
            *   在 `Draw` 方法中，如果处于 `IsDying` 状态：
            *   **马赛克化 (预处理)**: 在资源加载阶段预先生成像素化图片并缓存。
                *   **生成方式**: 创建一个临时的小尺寸 Image (例如原图的 1/10)，将原图绘制到小图上 (Filter: Nearest)，再将小图放大绘制回原尺寸的新 Image 上 (Filter: Nearest)。
                *   **运行时**: 怪物死亡时直接切换显示这张预生成的马赛克图，避免每帧进行缩放计算。
            *   **崩解下落**: 将图像分割成若干小块（Sprite），或者简单地让整体图像在 Y 轴上向下移动，同时透明度逐渐降低。
            *   **不规则运动**: 在下落过程中叠加随机的 X 轴偏移。
        *   **清理**: 当 `DeathTimer` 结束时，彻底移除怪物实体。

    3.  **动画切换**:
        *   状态机管理：Idle -> Move -> Attack。
        *   **优先级调整**: Move > Attack > Idle。
        *   **移动打断**: 只要检测到用户的移动输入，**立即中断**当前的攻击动作（无论是否播放完毕），强制切换到移动状态，以保证操作的流畅性和响应速度。
        *   **攻击锁定**: 只有在没有移动输入时，攻击动作才会完整播放，且在播放期间锁定状态（除非被移动打断）。
